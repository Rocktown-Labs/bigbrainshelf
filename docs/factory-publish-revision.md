# Publish gate and artifact revision contract, slice 1

The first slice closes the two reproduced fail-open paths (review findings
01 and 02). It does not claim the whole factory is release-safe. Generation
remains paused; this change requires review and merge and has not been deployed.

## Derived manifest

`packages/core/src/book-revision.ts` is the shared implementation for the hub
and future factory assembly integration. `book-revision/v1` is generated by
reading the actual bible, every chapter plan, planned line art and any declared
color art, plus the deliverable keys registered on the book row. It is not an
editable catalog file. Nothing writes a manifest into R2 in this slice.

- The actual bible's nonempty `conceptLadder` establishes expected chapters.
  Paginated plan listing must match it exactly. A missing, additional, empty,
  malformed or unreadable plan is a verification failure, never a smaller book.
- Stable page IDs are `S<n>:<index>` and `S<n>:finale`. Numeric chapter order is
  independent of storage listing order. The finale's approval index is the
  ordinary page count, matching the QC viewer.
- Every source/artifact entry records its key, role, byte length and SHA-256 of
  bytes actually read. Large deliverables are hashed as streams. Sources are
  hashed as raw bytes, so even a formatting-only source edit changes identity.
- The revision is SHA-256 of the canonical JSON payload (sorted object keys;
  sorted artifact keys; ordered page arrays), excluding the revision field.
  Same-size edits change identity. Reuploading identical bytes does not.
- Object ETags are a separate verification fence, not content identity. All
  captured objects must still exist at the same version before publication.
- Missing/unreadable declared artifacts fail capture. Undeclared deliverables
  are evaluated by the delivery checks; missing source/page inventory cannot
  be waived. Keys outside `books/<slug>/` are rejected intentionally.

This manifest binds the captured revision to actual bytes. It does **not**
establish that a PDF contains those pages, that its art passed QC, or that an
old approval reviewed those bytes. Those require composition receipts and
hash-bound approval/QA evidence in the following assembly slice. Until then,
existing delivery checks are still imperfect instruments.

## Publish request

`POST /api/editor/publish` requires `book_slug`; it no longer defaults to a
particular book. Inventory failure, unavailable approval reads, or incomplete
approvals (including finales) block publication. Approved counts use a set of
expected page identities, so duplicate rows and furniture cannot inflate it.

Audio readiness errors/null and every unknown/failing product-delivery check
block by default. Marketing readiness is not a book delivery requirement.
Readiness collection uses read-only mode: it does not seed casting or create QA
tables while deciding whether a book passes. Missing setup becomes unknown or
blocked evidence. A failed audiobook HEAD no longer assumes the file exists.

CG retains an explicit exception:

```json
{
  "book_slug": "example",
  "publishOverride": {
    "reason": "CG accepts this listed readiness exception for this release",
    "checks": ["audio", "delivery:audio-production"]
  }
}
```

Use the exact IDs in the current blocked response. Unknown/stale IDs, blank
reasons, anonymous operators and partial coverage of the blockers are refused.
Inventory and page approvals cannot be waived. The previous blanket
`audioGateOverride` flag does not authorize an exception. The admin editor now
shows the actual checks, requires confirmation and asks for a reason.

`publish_releases` stores a unique release ID, book slug, revision, complete
manifest JSON, audio/delivery facts, waived checks and reasons, operator, and
timestamp. The insert and status/price update share one D1 transaction. An
insert/update error rolls both back. SQL checks the book row and approvals again
inside the transaction; a concurrent change aborts it. This new journal is
separate from the historical audio-only `publish_overrides` table; historical
records are not rewritten. Success returns the release ID/revision and recorded
exception IDs. Existing release-announcement side effects remain post-commit.

## Deliberately open

- Assembly adoption: one manifest-based page sequence for all products; include
  coloring finales, refuse silent omissions/substitutions, and prove output PDF
  page identity against inputs. No assembler changed in this PR.
- Immutable artifact keys and an atomic release pointer. The final ETag check
  detects many concurrent changes but cannot eliminate the cross-storage race
  after that check. Fixed live keys can still change after publication.
- Approvals bound to artifact hashes and edition; QA facts bound to output
  hashes instead of timestamps/grace periods. Existing green approvals are
  still legacy evidence, not proof of review of a captured revision.
- Durable source SHA and build digest per deployment/run; no deployment code
  changes in this slice. Git canonical-source migration is already complete.
- Budget fail-open behavior is unchanged. Any outage-policy change requires
  CG's decision in a separate PR.
- Presenting the new generalized release journal in the admin history view.
  The existing history endpoint still serves the historical audio-only table.
- Performance profiling on real book sizes. Capture reads and hashes actual
  artifacts, then HEADs them, rather than trusting filenames/sizes. No production
  profiling or model calls were authorized or performed.

## Diagram claim notes

The v3 Mira "26 of 40" claim is unverified without exact artifact hashes and
must not be repeated as fact. Fenix's 97 ledger flags are not 97 independently
verified defective pages. Whole-PDF text flags include legitimate typeset text;
positional page mapping and failed-judge-as-clean behavior weaken cross-version
claims. Historical spend, stall duration, uncast counts and orphaned-work claims
still need their specific versioned records. No Doop frames or historical
judgment-run files were changed.

## Offline validation

The two original regression tests were run first and both failed on current
main: failed source read returned an empty page list, and null audio readiness
allowed publishing. Run the fixes and manifest/transaction faults with:

```sh
bun test tests/publish-gate-faults.test.ts tests/publish-revision.test.ts tests/publish-override-ui.test.ts
bun tests/publish-readiness.test.ts
bun tests/delivery-readiness.test.ts
bun tests/book-pages.test.ts
bun tests/public-slugs.test.ts
```

The historical publish-readiness fixture used Basil while the registry already
seeds Blaze; that failure was reproduced in the untouched audit checkout. The
fixture now uses the current name. Tests use in-memory SQLite and fake object
storage, including transactional rollback and multi-chunk artifact hashing.

Results for this slice: 22 focused tests passed, as did the existing
publish-readiness, delivery-readiness, book-pages, public-slugs, publish-prices,
and takes script suites. `bun run astro build` passed (including the modified
endpoint and admin script). `git diff --check` passed.

Two broader checks remain red independently of these fixes:

- `bun run build`: Astro builds, but the subsequent
  `scripts/prepare-worker-entry.mjs` import cannot find local `esbuild`.
  Packaging dependencies were not changed as part of this gate slice.
- `bun tests/releases.test.ts`: the fixture lacks the `user` table used by
  notification preferences. The same failure was reproduced in the untouched
  audit checkout. Release-announcement implementation was not changed.
